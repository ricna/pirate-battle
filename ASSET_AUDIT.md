# Authored assets and gameplay implementation audit

This audit implements the owner's 12 October gameplay brief, including hull collision and island impact feedback. All gameplay code is original to this project.

## Reproduce the inventory

```sh
node scripts/audit-assets.mjs
```

The report is [reports/asset-audit.json](reports/asset-audit.json). It inventories original/default/retina resources, reads PNG dimensions and WAV duration, parses the supplied ship XML and UI JSON, and finds candidate literal source references. A literal reference proves neither asset loading nor a real event; the usage/verification tables below supply that context.

The original default pack contains **234 PNGs**: 30 ships/boats, 67 ship parts, 5 effects, 96 tiles and 36 UI pieces. The ship XML describes 102 frames; the UI JSON describes 36. There are **27 supplied WAVs**. No ship-frame dimension mismatch was found. The ship XML contains no separate frame named foam, ring, wake, trail or splash.

`sample.png` and `sample_result.png` show crew, foam and debris as composition references. The XML confirms six crew variants and four wood variants, but does not define their behavior or a crew-count requirement. The owner's brief explicitly requires 2–5 crew per sinking. We do not claim that filename counts reveal undocumented company requirements.

## Texture policy and source ownership

- Pixi loads the shared default ship atlas for ships, parts, crew, debris, fire and explosions. Frames come from its XML; their rectangles are validated against the image.
- Pixi health indicators use the shared UI atlas and JSON regions. Health-fill crops include the frame's atlas offset, not coordinates measured from a standalone PNG.
- Tiled continues using its authored tilesheet, layout and collision objects. Animated deep water uses the explicitly configured standalone `tile_73.png` to avoid atlas repeat/bleed. The other layers are cached together and remain fixed.
- React/CSS may use individual UI PNGs and the supplied menu background, logo and reference ship thumbnails. They belong to a different rendering layer; they are not a second gameplay-sprite loading path.
- Default/retina are duplicate resolutions of the same art. The current gameplay atlas policy uses default resolution with logical world units and a capped canvas density. Retina resources are not loaded alongside the same default gameplay frames.
- The main menu board is drawn above logical size (up to 1.6× on the 1800×1000 reference), so it uses the retina `panel_menu`, `title_pirate_battle` and `ship_2` pieces. Its stretched buttons keep the shared default button states, which match the reference.
- Atlas frames/decoded images are bounded application caches. A match owns its transient sprites, cropped health fills and static map surface. Teardown unloads retiring GPU-context resources without destroying shared image sources.
- Missing required frames, rectangles or registered standalone references fail visibly. There is no PNG fallback for a missing atlas frame.

## All 27 WAVs: event and reproduction

All file names below end in `.wav`. `AudioConfig.requiredSounds()` enumerates exactly the supplied cues used by these mappings. Buffers are decoded once; counts in the opt-in audio observation record sources actually started, not just files fetched.

| File(s) | Event / scenario |
| --- | --- |
| `cannon_fire_1`, `cannon_fire_3` | Player front cannon; hold Space or Front cannon. Variants avoid immediate repetition. |
| `cannon_fire_2`, `cannon_fire_3` | Shooter front fire while in range and aligned. |
| `cannon_broadside` | Left/right complete salvo. It may alternate with the configured cannon variant; there is one cue per salvo, not per barrel. |
| `cannonball_water_hit_1`, `cannonball_water_hit_2` | A cannonball expires over free water. Coast impact does not masquerade as a water-only expiry. |
| `ship_wood_hit_1`, `ship_wood_hit_2` | Real damage applied to a hull. |
| `ship_collision` | Significant hull/island/boundary contact, Chaser ram, or configured coast impact. Threshold/cooldown prevents held-contact spam. |
| `ship_explosion_1`, `ship_explosion_2` | Real sinking explosion variants. |
| `ship_sinking` | Every real sinking, alongside the explosion rather than as an alternative that randomly replaces it. |
| `score_point` | Actual credited enemy kill and its single floating reward/HUD response. |
| `health_low` | First entry into the configured player low-health state. |
| `time_warning` | First entry into the final configured seconds of a battle. |
| `ocean_ambience_loop` | Active combat ocean bed; stops on pause, end and abandonment. |
| `ship_sailing_loop` | Real player speed above its threshold, including residual coasting; gain follows normalized speed and stops at rest. |
| `game_start` | Successful battle initialization. |
| `game_pause`, `game_resume` | Effective pause/explicit resume transitions. |
| `extra/576054__istudeny__pirat-battle`, `game_complete` | Real defeat/time completion, once per new result; not replayed on result refresh. These voices survive arena teardown. The owner's extra WAV replaces `game_over`, which remains unused source audio. |
| `ui_click` | Activating authored buttons. |
| `ui_back` | Returning to the menu. |
| `ui_open`, `ui_close` | Dialog mount/unmount. |
| `ui_hover` | Mouse pointer entering buttons/tabs; touch does not synthesize hover audio. |

Audio uses independent cosmetic variation, persisted mute/volume and at most 16 voices. Repeated effects alternate authored variants without immediately repeating when alternatives exist; combat playback-rate variation is independently sampled from the configured 0.94×–1.06× range. Higher-priority warnings/sinking/terminal cues can retire a lower-priority voice; sustained loops are not allowed to crowd out terminal audio. The opt-in observation exposes active/peak voices, decoded buffers and per-file playback counts. Browser/device listening is still needed for subjective mix approval; the inventory is not a claim that a human listened to all 27 cues in this session.
